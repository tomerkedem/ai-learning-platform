## 0. תקציר מנהלים - קראו את זה קודם

הממצא המרכזי שמעצב את כל הדוח: **המוצר הזה כבר לא ריק מתנועה.** ההפך. יש כאן מערכת framer-motion בוגרת ועקבית להפליא - 421 שימושים על פני 54 קומפוננטות, `useReducedMotion` מכובד כמעט בכל מקום, spring physics, stagger, `whileInView`, `AnimatePresence`, ו-EngineTrail עם autoplay.

המשמעות חדה: **המשימה כאן היא לא "להוסיף אנימציות". המשימה היא להדק, לאחד, ולהוסיף 3–5 אנימציות-על שמלמדות.**

הסכנה הכי גדולה לפרויקט הזה היא לא חוסר תנועה - אלא הצפה. כשכבר יש shimmer, מנטור מרחף, נקודות data זורמות, ping, autoplay ב-EngineTrail, ומאות מעברי spring - כל אנימציה נוספת מתחרה על אותו תקציב קשב. **תחושת פרימיום כאן תגיע מהפחתת רעש ומהאחדה, לא מהוספה.** לכן Tier 3 (מה לא לעשות) בדוח הזה ארוך ומחייב בדיוק כמו Tier 1.

שלושת המהלכים בעלי יחס ההשפעה-למאמץ הטוב ביותר (פירוט בסוף):
1. **קובץ tokens אחד לתנועה** - לאחד את כל ה-springs/easings/durations המפוזרים למערכת אחת. זה מה שהופך "אוסף פרקים" ל"מוצר אחד".
2. **רגע ה-Softmax (פרק 7)** - האנימציה שמלמדת הכי הרבה בכל הלומדה: scores → התלקחות → probabilities.
3. **סגירת הלולאה (פרק 11) וסגירת השער (פרק 12)** - שתי תנועות סיבתיות שתמונה סטטית לא יכולה להעביר.

## 1. שפת תנועה משותפת (Motion Language)

כרגע ערכי התנועה נכונים אבל **מפוזרים ומומצאים מחדש בכל קומפוננטה**. ראיתי לפחות: springs בערכי stiffness 110, 120, 130, 140, 160, 200, 220, 260, 300, 360, 380, 420 ו-damping שנע בין 16 ל-34; durations של 0.2, 0.22, 0.25, 0.3, 0.35, 0.4, 0.5, 0.6, 0.7. רובם בסדר - אבל ההבדל בין 130/18 ל-140/20 הוא לא כוונה עיצובית, הוא רעש. **פרימיום = עקביות.** הצעד הראשון הוא להפוך את הפיזור הזה לטבלה אחת.

### 1.1 טוקנים מוצעים (מאחדים את מה שכבר קיים, לא ממציאים חדש)

```ts
// motion/tokens.ts  (שכבת הצגה בלבד - הצעה למבנה)
export const DUR = {
  micro:   0.18,  // hover, tap, החלפת badge
  base:    0.30,  // כניסת אלמנט בודד, מעבר בין מצבים
  entrance:0.50,  // כניסת section / כרטיס גדול
  data:    0.70,  // מילוי בר, ספירת מספר
} as const;

export const EASE = {
  out:    [0.22, 1, 0.36, 1],   // ה-ease שכבר בשימוש ב-hero/layout - להפוך לברירת מחדל
  inOut:  [0.65, 0, 0.35, 1],   // ל-loops אמביינטיים
} as const;

export const SPRING = {
  data:   { type: 'spring', stiffness: 130, damping: 19 }, // מילוי בר/וקטור
  reflow: { type: 'spring', stiffness: 380, damping: 32 }, // layout/דירוג מחדש
  pop:    { type: 'spring', stiffness: 260, damping: 20 }, // הדגשה/כניסה דרמטית
  pill:   { type: 'spring', stiffness: 420, damping: 34 }, // layoutId pills (ModeSwitch וכו')
} as const;

export const STAGGER = 0.05; // delay בין פריטים ברשימה - תקרה: 0.5s סה"כ
```

### 1.2 כללי ברזל לשפה

- **שלוש משפחות spring בלבד** (data / reflow / pop) ועוד אחת ל-pills. כל ערך מחוץ לאלה צריך הצדקה.
- **stagger אחיד = 0.05s**, עם תקרה קשיחה של 0.5s לרשימה שלמה (כבר נעשה ב-TokenStream - להחיל בכל מקום).
- **כיוון RTL עקבי:** כניסות מחליקות מהציר הנכון (chat מ-x:24, engine מ-x:-24 - כבר קיים ב-TransparentLabLayout; זה התקן).
- **`useReducedMotion` הוא לא אופציה.** כל טוקן חדש חייב מצב reduced שמגיע מיד למצב הסטטי הסופי.
- **סולם הירארכי:** hero > section > כרטיס > אלמנט > micro. אלמנט קטן לא זז יותר דרמטית מהמכל שלו.

### 1.3 מה לתקן בשפה הקיימת (חוב תנועה)

| פריט | מצב היום | תיקון | סוג | השפעה | מאמץ | סיכון |
|---|---|---|---|---|---|---|
| פיזור ערכי spring/duration | ~12 ערכי stiffness שונים | לאחד ל-tokens.ts | חוויה | גבוהה | בינוני | אפס (רפקטור הצגה) |
| מספרים שלא סופרים | חלקם counter, חלקם טקסט סטטי (למשל top%/second%/margin% ב-ConfidenceMarginCard) | החלטה אחת: או הכל סופר או כלום | חוויה | בינונית | נמוך | jank אם יותר מדי counters בו-זמנית |
| loops אמביינטיים מרובים | shimmer + מנטור מרחף + נקודות data + ping פועלים יחד | חוק "תנועה אמביינטית אחת לכל מסך" | חוויה | גבוהה | נמוך | הסחה (זו הבעיה היום) |

### פרק 1 - מה קורה בין שאלה לתשובה

**מושג מרכזי:** הצינור המלא (tokens→meaning→ranking→confidence→decision). הכי קשה לתפיסה: **כוונות מתחרות בו-זמנית**, והפער (margin) בין הראשונה לשנייה הוא שמכריע.

### פרק 6 - המנוע לא רואה מילים, הוא רואה מספרים

**מושג מרכזי:** Token IDs (מפתחות חיפוש) ≠ Meaning Vectors (פרופיל נלמד). הכי קשה: **שני ניסוחים שונים לגמרי → IDs שונים לגמרי → וקטורי משמעות דומים.**

**מצב תנועה:** מצוין. ה-morph של word↔ID (`AnimatePresence mode="wait"` עם טריגר מתוזמן) הוא "רגע ה-wow" של הפרק; MeaningVectorLive עם spring + chevron "bumped"; SimilarMeaningPreview עם בר חפיפה spring.

### פרק 7 - Pipeline Cascade (מהמשמעות להחלטה)

**מושג מרכזי:** הצינור המלא vector→similarity→scores→**Softmax**→probabilities→decision. הכי קשה: **scores הם לא אחוזים; הם הופכים להסתברויות רק אחרי Softmax.** מטאפורת ה"מפל" דורשת זרימה אמיתית.

**מצב תנועה:** טוב - CascadeConnector עם נקודה זוהרת שנעה מטה, glow על שכבה פעילה, wave effect, springs. אבל **רגע ה-Softmax עצמו לא מודגש מספיק** ביחס לחשיבותו.

| המלצה | סוג | משרת | השפעה | מאמץ | סיכון |
|---|---|---|---|---|---|

### פרק 8 - Confidence Gate (שער הביטחון)

**מושג מרכזי:** margin פוגש סף; סיכון מעלה את הסף. הכי קשה: **אותה התפלגות בדיוק עוברת מ-"ענה" ל-"שאל" רק מהזזת סליידר** - הקלט לא השתנה, רק המדיניות.

**מצב תנועה:** מצוין מבחינה לימודית. GateDoors נפתחות/נסגרות (spring), מנעול ב-AnimatePresence, בר margin + סליידר, Answer Suppression. **דלתות השער הן בדיוק "אנימציה שמלמדת".**

| המלצה | סוג | משרת | השפעה | מאמץ | סיכון |
|---|---|---|---|---|---|
| **קישור חי בין הסליידר לדלתות בזמן הגרירה** - תוך כדי drag, הדלתות מגיבות רציף (לא רק בשחרור), ובדיוק ברגע החצייה יש "קליק" ויזואלי (מיקרו-snap) | מלמדת | "אותה התפלגות, מדיניות אחרת" - הרגע שהכל משתנה | גבוהה | בינוני | jank בגרירה; throttle + spring קצר |
| **משוב מגע במובייל על הסליידר** (ויזואלי, ואם זמין `navigator.vibrate` קצר ברגע החצייה) | חוויה | תחושת פרימיום על האינטראקציה המרכזית | בינונית | בינוני | נגישות: לא להסתמך על vibrate; ויזואלי תמיד |

### פרק 11 - Observation Loop (לולאת התצפית)

### פרק 12 - Control Layer (שכבת הבקרה)

**מושג מרכזי:** גם עם הבנה נכונה ותוצאת כלי מוצלחת - פעולה מסוכנת **עוצרת לאישור אנושי**. הכי קשה: **עצירה היא לא כישלון** - זה השער הנכון נסגר. לומדים מצפים ש"אוטומציה = לזוז".

## 4. דירוג עדיפויות בשלוש שכבות

### Tier 1 - אנימציות Hero שמלמדות (ההשפעה הגבוהה ביותר)

אלה מגלמות מושג שתמונה סטטית לא יכולה. **כאן להשקיע.**

1. **רגע ה-Softmax (פרק 7)** - scores→התלקחות→probabilities (סכום=100%). *הכוח/ההפיכה.*
2. **סגירת הלולאה (פרק 11)** - קשת מ-Decision חזרה ל-Tool Call. *המחזוריות.*
3. **סגירת השער (פרק 12)** - מחסום יורד, השלבים ננעלים. *הנעילה.*
4. **חשיפה מסונכרנת Chat↔Agent (פרק 13)** - סטייה בזמן אמת. *הפער.*
5. **בדיקת שערים סדרתית (פרק 10)** - match→input→risk→permission, עצירה בכישלון. *הזרימה המותנית.*
6. **הדגשת margin (פרקים 1+3)** - מדידת המרחק בין בר 1 ל-2. *הפער המכריע.*
7. **דלתא של "לא" (פרק 4)** - חיצי ↑/↓ סיבתיים על השלילה. *ההיפוך.*

### Tier 2 - פוליש פרימיום (חוויה)

- איחוד tokens.ts (בסיס לכל השאר).
- micro-interactions אחידים (tap/hover) בכל הלומדה.
- skeleton/empty/error states אחידים (במיוחד פרק 13 API).
- QualityMeter מדורג (פרק 14), stagger לברים (פרקים 1, 10).
- מעבר ניווט בין פרקים.
- סליידר מהירות ל-Replay (פרק 11).

### Tier 3 - מה לא לעשות (מלכודות דקורטיביות)

- **לא** להוסיף עוד loop אמביינטי לאף מסך. ה-Intro כבר על הגבול. חוק: **תנועה אמביינטית אחת לכל מסך.**
- **לא** confetti חוץ מסיום-לומדה יחיד.
- **לא** parallax / tsparticles רקע (החבילות מותקנות - פיתוי. רקע נע מתחרה עם תוכן לימודי).
- **לא** glow/pulse מתמשך על אלמנט שכבר העביר את המסר (ProbabilityMovementTrail, שכבות פרק 7).
- **לא** להנפיש כל בר/מספר. ConfidenceMarginCard לא חייב 3 counters בו-זמנית.
- **לא** remount גורף שמאפס מסך שלם (פרקים 2/3) - זו אנטי-אנימציה: היא *מסתירה* את השינוי.
- **לא** אנימציות כניסה על טבלאות-ייחוס (TokenIdTable, TokenColorLegend, RiskTable) - קריאוּת > ראווה.
- **לא** מורפינג טקסט אות-אות / typewriter מעבר לסמן הקיים - איטי ומעצבן בקריאה חוזרת.

## 6. מסילות בטיחות - עמידה לכל המלצה חיובית

כל המלצה ב-Tiers 1–2 לעיל מתוכננת לעמוד בששת התנאים. להלן איך, באופן כללי (ובכל המלצה ספציפית שמסומנת "פעם אחת ולהישאר סטטי"):

| מסילה | איך עומדים |
|---|---|
| 1. מצב סטטי קריא בסוף | כל אנימציית Tier 1 רצה **פעם אחת** ונחה במצב הסופי (Softmax מסתיים ב-100% מוצג; שער נשאר סגור; margin נשאר מסומן). אין אף המלצה שמשאירה את המסך באמצע תנועה. |
| 2. צמיד ל-Replay/עצירה | כל אנימציית הוראה מקבלת טריגר Replay (תבנית StagePlayer/AgentLoopReplay כבר קיימת - להרחיב). אמביינט ניתן לעצירה דרך reduced-motion. |
| 3. כיבוד `prefers-reduced-motion` | קיים כתקן בקוד (`useReducedMotion`). כל טוקן/המלצה חדשה חייבת מצב reduced שקופץ ישר לסטטי הסופי. ההמלצות לא מוסיפות תנועה שאי-אפשר לכבות. |
| 4. תנועה אחת בכל רגע | מפורש בהמלצות ה"גל" (פרק 7), "שערים סדרתיים" (פרק 10), "מסלול פעיל" (פרק 2). חוק "אמביינט אחד למסך" ב-Tier 3 אוכף את זה גלובלית. |
| 5. שכבת הצגה בלבד | כל ההמלצות הן ויזואליות. ה-engines (mockEngine, scoringEngine, gateLogic, toolEngine, loopEngine, controlEngine, coachEngine) **לא נגעתי בהם ולא ממליץ לגעת**. הערכים והלוגיקה נשארים; רק התצוגה זזה. |
| 6. לא מחליפה טקסט מסביר | כל ההמלצות מתלוות לטקסט הקיים, לא מחליפות אותו. הטקסט נשאר נגיש גם במצב reduced. |

**המלצות שלא עומדות והושמטו במכוון:** typewriter אות-אות (פוגע ב-2 ו-6), parallax רקע (פוגע ב-4 ו-5), confetti פר-תשובה (פוגע ב-1 ו-4), glow מתמשך אחרי מסירת מסר (פוגע ב-1). כולן ב-Tier 3.

## 7. סיכום - 3 עד 5 ההמלצות לפתוח מהן (יחס השפעה/מאמץ הטוב ביותר)

> מאיפה להתחיל, בסדר הזה:

1. **`tokens.ts` - מערכת תנועה אחת.** *סוג: חוויה · השפעה: גבוהה · מאמץ: בינוני · סיכון: אפס.* לוקח את כל ה-springs/durations המפוזרים ומאחד אותם. זה מה שהופך "14 פרקים" ל"מוצר אחד", וכל אנימציה שאחריו יורשת את העקביות. **חובה ראשון.**

2. **רגע ה-Softmax (פרק 7).** *סוג: מלמדת · השפעה: גבוהה מאוד · מאמץ: בינוני · סיכון: נמוך.* ההמרה scores→probabilities היא המושג שהכי קשה לתפוס בלי תנועה, וזו האנימציה היחידה שמלמדת אותו ישירות. התשואה הלימודית הגבוהה ביותר בלומדה לכל יחידת מאמץ.

3. **סגירת הלולאה (פרק 11) + סגירת השער (פרק 12).** *סוג: מלמדת · השפעה: גבוהה · מאמץ: בינוני · סיכון: נמוך.* שתי תנועות סיבתיות (מחזוריות, נעילה) שטקסט וחץ סטטי פשוט לא מצליחים להעביר. מאמץ דומה, מושגים משלימים - לעשות יחד.

4. **ניצחונות מהירים: stagger לברים (פרקים 1, 10) + QualityMeter מדורג (14) + micro-interactions אחידים.** *סוג: מעורב · השפעה: בינונית-גבוהה · מאמץ: נמוך · סיכון: נמוך.* אחרי tokens.ts אלה כמעט-חינמיים ומורגשים מיד בכל הלומדה.

5. **חשיפה מסונכרנת Chat↔Agent (פרק 13).** *סוג: מלמדת · השפעה: גבוהה מאוד · מאמץ: גבוה · סיכון: בינוני (orchestration).* פרק השיא; השדרוג הכי מורגש - אבל גם המורכב ביותר, ולכן אחרון מבין החמישה.

**המסר האחד אם שוכחים את כל השאר:** הקוד הזה כבר עשיר בתנועה. הקפיצה פי-100 לא תבוא מעוד אנימציות - היא תבוא מ**איחוד** (tokens.ts), מ**מחיקה** (Tier 3), ומ-**3–4 אנימציות-הוראה כירורגיות** ברגעים הקשים ביותר (Softmax, לולאה, שער, סטייה). איפוק הוא הפיצ'ר.
